[b]Volume Profile Library[/b]

A high-performance fixed range volume profile engine bundled with an embedded renderer. This library handles volume accumulation, core analytics (Point of Control and Value Area), and complex visual rendering natively. It features robust box and polyline display modes, handles absolute and recurring time ranges, and accepts lower-timeframe intrabar arrays to construct highly accurate volume profiles.

[b]Supported Configurations (As Seen in Example)[/b]
By wrapping the engine in your own script, you can expose a wide array of configurations to the user. The library natively supports processing all of the following parameters:
[list]
[*] [b]Timezone & Range Modes[/b]: Support for 'From Time' (single anchored profile), 'Between Times', 'Daily Anchor' (recurring at a specific time), and 'Daily Session' (recurring inside a specific session).
[*] [b]Profile Fidelity[/b]: Configure the number of price rows (up to 49), define the Value Area percentage, and optionally split each row into estimated buy/sell volumes based on intrabar close locations.
[*] [b]Visual Modes[/b]: Choose between traditional 'Boxes' (stacked volume rows), 'Polylines' (straight connective bands), and 'Curved Polylines', or disable all drawings while calculations continue.
[*] [b]Appearance & Gradients[/b]: Natively handles coloring for bull/bear/total volume, fading volume out outside the Value Area, rendering gradient color bands within polylines, and highlighting the Range Box and Point of Control (POC) line/label.
[*] [b]History Retention[/b]: Retain multiple historical recurring profiles on the chart at once without constantly recalculating them.
[/list]

[b]How to Use Correctly[/b]
To use this library effectively, the consuming indicator or strategy must handle three critical tasks:
[list=1]
[*] [b]Declare Engine State[/b]: Create a persistent state instance using `var profileState = VP.createState()`. The engine requires this state to manage arrays, recycle drawings, and persist historical sessions across bars.
[*] [b]Allocate Limits[/b]: Because the library manages drawing native Pine boxes, lines, and polylines, your main script must provide it with a large enough budget. You must add these limits to your `indicator()` or `strategy()` declaration (e.g., `max_boxes_count = 500`, `max_polylines_count = 100`).
[*] [b]Fetch Intrabar Data[/b]: Pine Script restricts `request.security_lower_tf()` inside loops and libraries. You must fetch these arrays (High, Low, Close, Volume) at the global scope of your consumer script and pass them directly into `VP.update()`.
[/list]

[b]Example Integration[/b]
[pine]
import OneCleverGuy/VolumeProfileLibraryTESTA/8 as VP

// 1. Declare persistent state and assemble config
var VP.ProfileState profileState = VP.createState()
var VP.ProfileConfig profileConfig = VP.ProfileConfig.new()

// 2. Fetch lower-timeframe data for volume accuracy
string ltf = timeframe.in_seconds() > 60 ? "1" : timeframe.period
[ltfHighs, ltfLows, ltfCloses, ltfVolumes] = request.security_lower_tf(syminfo.tickerid, ltf, [high, low, close, volume])

// 3. Update the engine on every bar
profileState := VP.update(profileState, profileConfig, true, ltfHighs, ltfLows, ltfCloses, ltfVolumes)

// 4. Retrieve statistics for your own logic
[poc, vaHigh, vaLow] = VP.getMostRecentLevels(profileState)
[/pine]

[b]Important Notes[/b]
[list]
[*] Bars without lower-timeframe coverage will automatically fall back to the chart bar's data during accumulation.
[*] Ensure you guard against missing volume in your main script (e.g., `if not na(volume)`), as the engine strictly requires volume data to function.
[/list]

[b]Update - Expanded Rendering and Session Management[/b]

This update extends the original engine while preserving the same state-driven integration pattern. The library now manages a broader visual system, exposes more retained statistics, and resolves Pine drawing limits automatically for recurring profiles.

[b]What Changed[/b]
[list]
[*][b]Expanded profile rendering[/b]: Box, straight-polyline, and curved-polyline displays now share the same row calculation. Polyline regions support None, Solid, and Gradient fill modes.
[*][b]Adaptive gradient allocation[/b]: Gradient fills automatically use between three and eight ribbons per region. The engine reduces the ribbon count before reducing the number of fully drawn sessions.
[*][b]Independent level visuals[/b]: Point of Control, Value Area High, and Value Area Low lines now have independent visibility, style, width, color, and label controls.
[*][b]One-session level extension[/b]: Completed recurring-session levels can extend through the following session. The newest completed session follows the current bar until its successor is available.
[*][b]Budget-aware history[/b]: The requested history count can exceed the number of row profiles that fit Pine's drawing limits. Fully drawn sessions are retained first; remaining sessions keep their requested range box and level drawings.
[*][b]Range-box priority[/b]: When range boxes are enabled, the engine reserves one for every represented session before allocating boxes to row profiles.
[*][b]Retained diagnostics[/b]: ProfileState now exposes the resolved full-history count, lower-tier history count, fill-band count, latest bar count, and latest total volume.
[*][b]Memory cleanup[/b]: Source-entry arrays are released when a profile completes, and row arrays are released when a session leaves the fully drawn tier.
[/list]

[b]Updated Integration Requirements[/b]
[list]
[*]Use the current library import and continue storing ProfileState and ProfileConfig with var.
[*]Pass fixed input.time timestamps directly. The timezone config applies to recurring anchors, recurring sessions, and level-label dates.
[*]Declare max_boxes_count = 500, max_polylines_count = 100, max_lines_count = 500, and max_labels_count = 500 in the consuming script.
[*]Continue fetching lower-timeframe High, Low, Close, and Volume arrays in the consumer. Missing intrabar coverage falls back to chart-bar data.
[*]Use PolylineFill.None, PolylineFill.Solid, or PolylineFill.Gradient through ProfileConfig.polylineFill instead of manually selecting a gradient-band count.
[/list]

[b]Current Integration Shape[/b]
[pine]
import OneCleverGuy/VolumeProfileLibraryTESTB/3 as VP

var VP.ProfileState profileState = VP.createState()
var VP.ProfileStyle profileStyle = VP.ProfileStyle.new()
var VP.ProfileConfig profileConfig = VP.ProfileConfig.new(
    polylineFill = VP.PolylineFill.Gradient,
    showPoc = true,
    showValueAreaLines = true,
    extendLevelsExtraSession = false,
    style = profileStyle)

string ltf = timeframe.in_seconds() > 60 ? "1" : timeframe.period
[ltfHighs, ltfLows, ltfCloses, ltfVolumes] = request.security_lower_tf(
    syminfo.tickerid, ltf, [high, low, close, volume])

profileState := VP.update(
    profileState, profileConfig, not timeframe.isseconds,
    ltfHighs, ltfLows, ltfCloses, ltfVolumes)

[poc, vaHigh, vaLow] = VP.getMostRecentLevels(profileState)
[/pine]
